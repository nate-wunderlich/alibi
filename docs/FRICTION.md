# SDK FRICTION -- alibi

1. (2026-09-22, deepspace 0.33.1) The reference repo READMEs (doodlechain, threadhunt) show the top-level form `npx deepspace login`. In 0.33.1 the top-level `npx deepspace whoami` is an unknown command and the CLI suggests `deepspace auth whoami`; the docs' Installation page uses `auth login` and `auth whoami`. Repro: npx deepspace@0.33.1 whoami.
2. (2026-09-22, deepspace 0.33.1, WSL2 Ubuntu 24.04) `npx deepspace auth login` prints "Opening browser..." but on stock WSL no browser opens and no warning is shown. Copying the fallback link with Ctrl+C cancels the login (the terminal shows "Canceled"), and the canceled link then returns a bare 404. Fix that worked: sudo apt install wslu, then BROWSER=wslview npx deepspace auth login. Suggestion: detect WSL and say so, and state that the link dies when the command exits.
3. (2026-09-23, create-deepspace 0.33.1) The docs Installation page (built with 0.30.1) says the scaffolder registers the app and makes the initial commit. In 0.33.1 it does neither: DEEPSPACE_APP_ID stays "__APP_ID__", the repo has no commits, the branch is master, and vite build fails until `npx deepspace app init` runs. The scaffolder's own output explains this, but the docs contradict it. Repro: npm create deepspace@0.33.1 x, then npm run build.
4. (2026-09-23, deepspace 0.33.1) Integration image and speech endpoints return base64 data URIs, but server code (actions, jobs) has no documented way to store a file and get a URL; ActionTools has no file method, and uploads are client-side (useR2Files) or through the file proxy with identity headers. Generated media therefore needs a hand-built round trip.
5. (2026-09-23, deepspace 0.33.1) Test-account emails are global across all DeepSpace developers, so the example addresses in the scaffold (tests/collab.spec.ts, e.g. a@deepspace.test) are already taken and `test accounts create` refuses them with test_account_email_taken. Suggestion: use a per-developer example in the scaffold, such as <app>-<user>-a@deepspace.test.
6. (2026-09-23, deepspace 0.33.1, WSL2 Ubuntu 24.04) `deepspace test run` downloads Playwright browsers (~300 MB) but not their system libraries; on stock WSL the headless shell fails with "libasound.so.2: cannot open shared object file". Fix: sudo apt install libasound2t64. Suggestion: check browser dependencies up front and print the install command.
7. (2026-09-23, deepspace 0.33.1) Server-side file storage works but is undocumented: platformWorkerFetch to /internal/files/upload?scope=app with x-app-identity-token, x-app-id, and x-user-id stores a file (the same request the app's /api/files proxy builds). The upload response's url points at platform-worker.deep.space/api/files/..., which returns 404 ("No route for GET /api/files/..."); only the app-origin form https://<app>.app.space/api/files/<key>?scope=app serves the file. Also, a local dev server writes to the real platform bucket, not a sandbox. Suggestion: an ActionTools file method (e.g. tools.files.upload) that returns an app-relative URL.

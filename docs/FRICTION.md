# SDK FRICTION -- alibi

1. (2026-09-22, deepspace 0.33.1) The reference repo READMEs (doodlechain, threadhunt) show the top-level form `npx deepspace login`. In 0.33.1 the top-level `npx deepspace whoami` is an unknown command and the CLI suggests `deepspace auth whoami`; the docs' Installation page uses `auth login` and `auth whoami`. Repro: npx deepspace@0.33.1 whoami.
2. (2026-09-22, deepspace 0.33.1, WSL2 Ubuntu 24.04) `npx deepspace auth login` prints "Opening browser..." but on stock WSL no browser opens and no warning is shown. Copying the fallback link with Ctrl+C cancels the login (the terminal shows "Canceled"), and the canceled link then returns a bare 404. Fix that worked: sudo apt install wslu, then BROWSER=wslview npx deepspace auth login. Suggestion: detect WSL and say so, and state that the link dies when the command exits.
3. (2026-09-23, create-deepspace 0.33.1) The docs Installation page (built with 0.30.1) says the scaffolder registers the app and makes the initial commit. In 0.33.1 it does neither: DEEPSPACE_APP_ID stays "__APP_ID__", the repo has no commits, the branch is master, and vite build fails until `npx deepspace app init` runs. The scaffolder's own output explains this, but the docs contradict it. Repro: npm create deepspace@0.33.1 x, then npm run build.
